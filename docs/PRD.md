# PRD — Today I Learnt (Obsidian study session tracker)

**Status:** v1.0, implemented
**Author:** (you)
**Last updated:** 2026-10-31
**Target:** Obsidian community plugin

---

## 1. Summary

An Obsidian plugin that tracks a focused **study session**: you start it, work through your vault,
and stop it. It then writes a block into that day's daily note showing the **path you took through
your notes**, and optionally a set of **"Grill me" recall questions** on what you studied.

The questions come from the **Claude API** (user supplies their own key). When no key is set or a
call fails, the plugin falls back to **offline questions** built from the session itself, so the
core loop always works without the network.

The plugin is dedicated to Obsidian. It captures activity inside the vault only, and does not
plan to take input from other tools (browser extensions, web search, external servers).

---

## 2. Goals

- Let a user explicitly **start and stop** a study session.
- **Capture vault activity** during the session: notes opened, created, modified, renamed and
  deleted, time per note, links followed, tags added.
- On stop, write a **study block** into the **daily note**, inside machine-findable markers.
- Show **how the user moved through their notes** (a diagram and a linked chain).
- Optionally add **recall questions** generated by Claude (BYO key), degrading gracefully to
  offline questions.
- Be **publishable to the Obsidian community directory**.
- Keep **output** pluggable, so the daily note can later be joined by publish targets.

## 3. Non-goals

- Inferred / automatic session boundaries (idle detection). Sessions are explicit start/stop.
- Capturing anything outside the vault: browser activity, web searches, other apps, PDF reading
  position. Capture is, and will stay, Obsidian-only.
- Integrations that feed the plugin from other tools (Chrome extension, MCP server, etc.).
- Mobile-specific features beyond "it works on mobile."

---

## 4. Users & motivation

- **Primary user:** you — someone doing deliberate, self-directed study inside Obsidian who wants
  an automatic record of each session and a quick way to test what stuck.
- **Secondary users:** other Obsidian users with a daily-note habit who want effortless session logs.

### User stories
- *As a learner,* I can run "Start study session" so the plugin begins recording my activity.
- *As a learner,* I can run "Stop study session" and immediately see my session in today's daily
  note: how long, which notes, and the path between them.
- *As a learner,* I can turn on **Grill me** and add a Claude API key to get recall questions on
  what I studied.
- *As a privacy-conscious user,* with Grill me off or no key set, nothing leaves my device.
- *As a user,* if Obsidian reloads or crashes mid-session, my session is not lost.

## 5. Architecture

One capture layer, one core, pluggable summarizers and sinks, connected by one contract — the
**session record**.

```
 Vault activity            Core                          Sinks
 (ActivityTracker) ──>  SessionStore ──> derive() ──┬──> Daily-note writer
                        RecordStore (JSON)          └──> Publish targets (later)
                                │
                                ▼
                         Summarizer (pluggable)
                          ├─ Claude API  (Grill me, BYO key)
                          └─ Template    (offline fallback)
```

### Code layout

| Path | Role |
|---|---|
| `src/main.ts` | Plugin lifecycle: commands, ribbon, status bar, start/stop flow. |
| `src/capture/activityTracker.ts` | Listens to vault, workspace and metadata cache; emits `SessionEvent`s. |
| `src/core/sessions.ts` | `SessionStore`: holds the running session, drops events while idle. |
| `src/core/derive.ts` | Pure: events → `DerivedStats` (time per note, visit order, transitions). |
| `src/core/block.ts` | Pure: renders the daily-note block and upserts it into note text. |
| `src/core/format.ts` | Small formatting helpers (durations, titles, wikilinks). |
| `src/storage/recordStore.ts` | Saves session records and the running session as JSON. |
| `src/summarizers/` | `claude.ts`, `template.ts`, and `index.ts` (picks one, handles fallback). |
| `src/sinks/dailyNotes.ts` | Finds or creates the daily note and writes the block. |
| `skills/grill-me-study/SKILL.md` | The question-writing prompt, bundled into `main.js`. |

### Seams
1. **Session record → Summarizer.** One interface, `summarize(record) → markdown`. The caller
   (`summarizers/index.ts`) always gets a summary back and never branches on backend.
2. **Record → Sink.** Sinks implement `write(record)`. v1 has one sink (daily note). Publish
   targets are future sinks reading the same record; no schema change is needed for them.

`core/` and `types.ts` stay free of `obsidian` imports so they remain pure and unit-testable.

## 6. The session record (core contract)

Stored as JSON, one file per session, in the plugin's own folder:
`.obsidian/plugins/today-i-learnt/sessions/<id>.json`. This keeps records out of the visible vault.

```json
{
  "id": "2026-10-20T09-03-12-000Z-session",
  "start": "2026-10-20T09:03:12.000Z",
  "end": "2026-10-20T09:51:40.000Z",
  "durationSec": 2908,
  "events": [
    { "ts": "...", "type": "note.open",   "path": "Topics/Transformers.md" },
    { "ts": "...", "type": "note.modify", "path": "Topics/Transformers.md", "bytesDelta": 740 },
    { "ts": "...", "type": "note.create", "path": "Daily/scratch.md" },
    { "ts": "...", "type": "link.follow", "from": "A.md", "to": "B.md" },
    { "ts": "...", "type": "tag.touch",   "path": "A.md", "tag": "#attention" }
  ],
  "derived": {
    "notesTouched": ["Topics/Transformers.md", "..."],
    "created": ["Daily/scratch.md"],
    "timePerNoteSec": { "Topics/Transformers.md": 1200 },
    "tagsTouched": ["#attention"],
    "linksFollowed": 1,
    "visitOrder": ["Topics/Transformers.md", "B.md"],
    "transitions": [{ "from": "Topics/Transformers.md", "to": "B.md", "viaLink": true }]
  },
  "summary": {
    "backend": "claude-api",
    "markdown": "...",
    "generatedAt": "2026-10-20T09:51:45.000Z"
  }
}
```

- `summary` is present only when Grill me is on. `summary.fallbackReason` is set when Claude
  failed and the template was used.
- The running session is also saved as `sessions/active.json` every 30 s and on unload, and
  resumed on the next load. It is removed when the session stops.

### Event schema rules
- Event `type` is named after the thing acted on (`note.open`, `link.follow`).
- Events hold only plain JSON values, never Obsidian objects such as `TFile`.
- Each type has a fixed set of fields, modelled as a discriminated union in `src/types.ts`.
- Consumers ignore types they don't recognise, so records stay readable as types are added.

## 7. Capture

| Event | How it is detected |
|---|---|
| `note.open` | `workspace` `file-open`; switching back to the same tab is not a new open. The note already open at start is recorded. |
| `note.create` | `vault` `create`, registered after layout is ready (it fires for every file on load). |
| `note.modify` | `vault` `modify`, merged into one event per burst of edits (ends after 10 s quiet), with `bytesDelta`. |
| `note.rename` / `note.delete` | `vault` `rename` / `delete`. Derived stats resolve every path to its final name. |
| `link.follow` | Inferred: Obsidian has no "link clicked" event, so a new open counts as a followed link when the previous note links to it. |
| `tag.touch` | `metadataCache` `changed`, for tags not present when the note was first seen. |

Only Markdown notes are tracked.

**Time per note** is the time a note was the active one, with any single gap capped at 20 minutes
so leaving Obsidian open doesn't inflate study time.

## 8. Output: the daily-note study block

Written on stop into the daily note of the day the session **started**. Obsidian comment markers
(`%% %%`, hidden in reading view) delimit the block; a `[!study]` callout is the visible part.

```markdown
%% study-session:start id=2026-10-20T09-03-12-000Z-session %%
> [!study] Study session · 09:03–09:51 · 48m
> **Notes:** 6 touched, 2 created
>
> **Path**
> ```mermaid
> flowchart LR
>     n0["Kafka"]
>     n1["Partitioning"]
>     n0 --> n1
>     class n0,n1 internal-link;
> ```
> [[Kafka]] → [[Partitioning]]
>
> **Grill me**
> *How ordering guarantees shape everything in Kafka.*
> 1. Why does [[Partitioning]] only guarantee order within a partition?
%% study-session:end %%
```

- **Notes line:** shown when *Show note counts* is on.
- **Path:** a Mermaid flowchart (solid arrow = followed a link, dotted = reached another way;
  nodes are clickable) plus a wikilink chain in first-visit order. Capped at 20 diagram nodes and
  40 chain links.
- **Grill me:** shown only when Grill me is on. If the template was used as a fallback, a line
  says why ("*Offline questions used: …*").
- **Idempotent:** a block with the same `id` is replaced in place; otherwise it is appended.
  Nothing outside the markers is touched. Multiple sessions in a day appear as stacked blocks.
- **Finding the note:** in *Automatic* mode, the Daily notes / Periodic Notes folder, format and
  template are used, and the note is created if missing. Otherwise (or with no daily notes plugin)
  the configured path pattern is used, e.g. `Daily/{{date}}.md` or `{{date:DD-MM-YYYY}}`.
- If writing the note fails, the record is already saved, and the user gets a notice.

## 9. Grill me (summarization)

### Interface
```ts
interface Summarizer {
  summarize(record: SessionRecord): Promise<string /* markdown */>;
}
```

### Backends
| Backend | When used | Network |
|---|---|---|
| **Claude API** | Grill me on and a key is set | Sends session data to Anthropic. |
| **Template** | Grill me on but no key, or the API call failed | None |

With Grill me off, no summarizer runs and the block shows only the path.

### Claude API backend
- **BYO key**, entered in settings. Model: Haiku (default) or Sonnet.
- System prompt is the bundled `grill-me-study` skill plus a batch output format: one italic line
  naming the connecting thread, then a numbered list of questions, each naming its source note as
  a `[[wikilink]]`. No answers.
- User prompt: duration, the path through the notes, notes by time spent, tags, and (if *Send note
  content* is on) excerpts of the notes.
- Size limits: excerpts from at most 10 notes, 1,500 characters each, 30,000 total; at most 30
  notes and transitions listed by title.
- Uses Obsidian's `requestUrl`. Retries once after 2 s on 429/503/529. Any failure (no key, bad
  key, network, unexpected response) falls back to the template, with a short reason that never
  includes request details.
- Question count: 3 / 5 / 8.

### Template backend
Pure function of the record. One italic overview line ("*48m across 6 notes (2 created), followed
3 links.*") and up to 5 questions built from the path ("How does [[B]] build on [[A]]?"), created
notes, or the most-studied notes.

## 10. Settings

**Daily note**
- *Show note counts* — toggle the Notes line.
- *Find daily note* — Automatic (Daily notes / Periodic Notes) or Use path below.
- *Daily note path* — pattern with `{{date}}` / `{{date:FORMAT}}`.

**Grill me**
- *Grill me* — on/off (default off). The options below appear only when it is on.
- *Claude API key* — password field, with a warning that it is stored in plain text in
  `data.json`, syncs with the vault, and that note content is sent to Anthropic.
- *Model* — Haiku or Sonnet.
- *Number of questions* — 3, 5 or 8.
- *Send note content* — off sends only titles, tags and times.

## 11. Commands & UI

- Commands: **Start study session** (only while idle), **Stop study session** (only while running).
  No default hotkeys.
- Ribbon icon and status bar item both toggle a session. Status bar shows elapsed time, refreshed
  every 30 s.
- Notices on start, stop, Claude fallback, and daily-note write failure.

## 12. Future: publish sinks

Whatever is learned in a session should be shareable — either the block/summary (curated) or the
source notes (full fidelity). This is modelled as additional **sinks** implementing
`Sink.write(record)`, alongside the daily note:
- Export a session bundle (block + touched notes) as markdown / folder.
- Publish targets such as Obsidian Publish, a gist, or copy-to-clipboard.

The record already stores the paths and summary this needs, so no schema change is required.
Capture stays Obsidian-only.

---

## 13. Risks & review considerations

- **Secret storage.** The API key lives in plaintext in `data.json` and syncs with the vault.
  Warned in settings and README.
- **Community directory review.** Sending vault content to a third party must be disclosed in the
  README. Grill me is off by default and the plugin is fully useful without the network.
- **Context limits.** Handled by the size limits in §9.
- **Daily-note compatibility.** Respect Daily/Periodic Notes conventions; only ever write inside
  the markers.

---

## 14. Decisions (formerly open questions)

- **Content sent to Claude:** excerpts by default when Grill me is on, with *Send note content* to
  restrict to titles, tags and times.
- **Same session id already in the note:** replace the block in place.
- **Review before writing:** no; the block is written immediately on stop and can be edited by hand.
- **Multiple sessions per day:** stacked blocks, one per session.
- **Prose summary vs. questions:** questions. Recall practice is more useful than a recap, and the
  path already shows what was covered.

## 16. Success criteria

- Start → work → stop produces a correct, well-formatted study block in the daily note.
- With a key: questions are genuinely useful for recall. Without one: offline questions still read well.
- A reload or crash mid-session loses at most 30 s of activity.
- Accepted into the Obsidian community directory.
